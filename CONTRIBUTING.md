# Contributing Guide

First off — thank you for considering contributing! This repo is intentionally built to be friendly for **first-time open-source contributors** as well as experienced engineers.

## 🧑‍💻 Setup

1. Fork the repo
2. Clone your fork: `git clone https://github.com/<you>/fullstack-starter.git`
3. Install deps: `npm install`
4. Create a branch: `git checkout -b feat/my-feature`
5. Make your changes
6. Run `npm run lint` before committing
7. Commit using clear messages (e.g. `fix: navbar overflow on mobile`)
8. Push and open a Pull Request

## 🆕 New to open source?

Totally fine! Here's the simplest path:

1. Find an issue labeled `good first issue`
2. Comment "I'd like to work on this" so it gets assigned to you
3. Ask questions in the issue if anything is unclear — no question is too basic
4. Open a PR referencing the issue (e.g. `Closes #12`)

## 🧭 Guidelines

- Keep PRs focused — one feature/fix per PR is easier to review
- Match the existing code style (TypeScript, functional components, Tailwind utility classes)
- Add comments for non-obvious logic
- If adding a feature, update the README if relevant
- Be respectful in code reviews — see [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md)

## 🐛 Reporting Bugs

Use the Bug Report issue template. Include steps to reproduce, expected vs actual behavior, and screenshots if UI-related.

## 💡 Suggesting Features

Use the Feature Request issue template. Explain the problem it solves, not just the solution.

## 🔍 Reviewing PRs

Even if you don't code, you can help by testing open PRs locally and leaving feedback. Reviews from anyone are welcome and appreciated.

---

Every contribution — a typo fix, a bug report, a big feature — is valued. Thanks for being here. 🙏
